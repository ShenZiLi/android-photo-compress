# 本地 Git 规范

依据用户明确要求：每次变更都提交本地 Git。

- 一个提交对应一个能说明目的的完成变更单元。代码、文档、Trellis 任务和会话记录同样适用。
- 提交前查看 `git status`、本次差异与 `git diff --check`；对实现变更执行与风险相符的检查。
- 只暂存本次任务文件，避免带入用户或其他工作的修改。
- 提交信息描述实际变化，例：`chore: initialize Trellis and local commit conventions`。
- 提交无需再次请求许可；推送和发布不由本地提交权限推导。
- 不把未验证的实现写成已通过，不提交个人媒体、恢复副本、密钥或签名资料。
- 修改会话记录后的变更也需提交；必要时使用 Trellis 的 session auto-commit。
- 交付报告包含提交编号、实际检查和剩余限制。
