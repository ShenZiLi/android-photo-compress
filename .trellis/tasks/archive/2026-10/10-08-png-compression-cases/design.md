# 实现边界

三个行为缺口分别在 PngCompressor 的像素闸门/透明拒绝、CompressionEngine 的 PNG JPEG 目标选择、AppViewModel 的批次并发选择。

交付时同步 PNG 规范和 README 的当前支持范围，避免文档继续声称透明 PNG 会被跳过；验证证据保存在本任务 research 中。

1. `PngCompressor.MAX_PARALLEL_PIXELS = 16_000_000L` 仅用于调度，不再作为压缩拒绝条件。保留合法尺寸与行缓冲边界；实际解码前按源数组、单张位图、行缓冲和必要余量检查可用堆。8 位按 ARGB_8888 的 4 字节/像素，16 位保守按平台实际可返回 RGBA_F16 的 8 字节/像素预算。释放源位图后再解码输出 JPEG，避免两张整图常驻。
2. 可变 ARGB_8888/RGBA_F16 位图由软件 Canvas 在原色彩空间逐行以 DST_OVER 铺白，最后 alpha 为 255；不创建第二张整图，结束时解除 Canvas 对源位图引用。不使用强制经 sRGB 的整行整数像素往返。
3. JPEG 文件名在现有媒体锁内、prepare 之前决定：优先原名 `.jpg`，冲突时依次 `_1.jpg`、`_2.jpg`。为数字后缀与扩展名预留 255 字节 UTF-8 文件名预算，必要时按完整 Unicode 码点缩短基名。prepare 和改名仍检查目标不可覆盖；外部在选择后占用路径时沿用回滚保护。恢复日志、账本和刷新均使用选定的同目录路径。
4. AppViewModel 在当前已有的大 HEIC 单路条件之外增加大 PNG/未知尺寸 PNG 条件，整体批次单路。提交只暂存此 PNG 增量，保留原有 HEIC 未提交改动。

不更改 APNG、HDR、低色深、交错或未知危险块规则，不缩小图片尺寸，不更改数据库结构或媒体恢复事务，不修改版本号和 HEIC 实现。
