# 安卓照片压缩 App（普通照片/实况照片/视频）

## Goal

在真我 GT7 Pro / ColorOS 16（Android 16）上，对手机内的普通照片、实况照片、视频执行"肉眼不可见细节损失"的有损压缩，显著减小体积；压缩后就地替换原文件，保持存储位置与创建/修改时间不变，保留地点、相机等扩展信息；每份媒体只处理一次，用唯一编号识别已处理项；界面现代简洁、使用逻辑清晰。

带来的用户价值：直接释放存储空间并减少手动清理；不改变相册使用习惯（位置、时间、实况属性保持不变）；避免重复压缩造成画质逐次下降。

## 背景与证据

- 目标环境：真我 GT7 Pro（realme），ColorOS 16（用户表述；实际固件与相册版本以真机读取为准），Android 16。
- 样张 `C:\Users\Admin\Desktop\实况图片.jpg` 实测 12,478,846 字节（约 11.9 MB），为有效 JPEG。
- 该样张是 OPPO/oplus 实况照片：XMP 位于偏移 23664–25334，声明
  `GCamera:MotionPhoto="1"`、`GCamera:MotionPhotoVersion="1"`、
  `GCamera:MotionPhotoPresentationTimestampUs="1220005"`、
  `OpCamera:MotionPhotoOwner="oplus"`、`OpCamera:OLivePhotoVersion="2"`、
  `OpCamera:MotionPhotoPrimaryPresentationTimestampUs="1220005"`、
  `OpCamera:VideoLength="5116097"`。
- 采用 Google Motion Photo v2 的 `Container:Directory` + `Item` 语义，共三项：
  1. `Primary` image/jpeg，`Length=0`（主图，长度隐含）；
  2. `GainMap` image/jpeg，`Length=430057`（HDR 增益图）；
  3. `MotionPhoto` video/mp4，`Length=8331026`。
- 内嵌视频为 HEVC（`hvc1` / `hvcC`）+ AAC（`mp4a`），品牌 `isom`/`mp42`；MP4 起始偏移约 4,147,824。
- 由此得出：实况照片压缩必须同时正确处理 **主图 + GainMap + 内嵌 MP4** 三段，并在压缩后重算 XMP 的 `Item:Length`/`Item:Padding`、`OpCamera:VideoLength` 及 MP4 内部偏移，否则相册将无法识别或播放。
- 本机构建环境：JDK 17、Gradle 8.14.5、Android SDK 位于 `C:\Users\Admin\AppData\Local\Android\Sdk`，已有 `android-36` 平台、build-tools 36.1.0、platform-tools(adb)、NDK 30。项目当前为空目录（仅 Trellis 初始化）。
- 系统媒体格式调研（2026-10-04）结论见 [research/coloros-media-formats.md](./research/coloros-media-formats.md)：ColorOS 相册自带「截屏录屏」「动图」「最近删除(30 天)」等图集；OPPO 相机照片格式为 JPG/HEIF/RAW。**当前 D6 覆盖不全面**，存在 6 处明确缺口（PNG 截图、GIF/动态 WebP、WebP/BMP、AVIF 图片、RAW/DNG、视频容器）与 4 处风险缺口（普通照片 GainMap/Ultra HDR、人像模式景深信息、10-bit HDR/杜比视界/O-Log、慢动作与延时的播放速率语义）。

## 已确认决策

- D1 原文件保留：压缩成功并通过校验后，原文件移入**应用私有回收站**（默认保留 **30 天**，期间可一键还原），而不是立即永久删除。
- D2 处理触发：首版仅"用户手动选择后压缩"；自动扫描全库不在首版范围。
- D3 交互结构：首页总览看板 + 未压缩页 + 已压缩页 + 设置页（含回收站入口），四个主要页面。
- D4 设置页"压缩比例"= **质量档位**（每类给若干档，默认"肉眼不可见"档），最终体积由算法决定；不采用"目标体积百分比"。
- D5 去重编号存放：**本地数据库 + 压缩后文件内自有 XMP 元数据标记**（唯一编号 + 压缩器版本 + 时间）。重装或清除应用数据后仍可识别已压缩文件，避免二次压缩。
- D6 首版格式与编码覆盖：
  - 照片：JPEG、HEIF/HEIC（相机原生格式）
  - 实况照片：JPEG 主图 + GainMap + 内嵌 MP4
  - 视频：MP4 容器，HEVC / H.264 / AV1 / VP9 编码（10-bit HDR 见 D11）
  - 音频：AAC
- D7 实况照片的内嵌视频按"实况照片"质量档位**重编码**（样张中视频约占 2/3 体积，不重编码则收益极小）。
- D8 界面方向：Jetpack Compose + Material 3 / Material You，跟随系统动态取色与深浅色自适应。
- D9 文件访问：申请"所有文件访问"(MANAGE_EXTERNAL_STORAGE)，用直接文件读写完成原地改写与时间保留；不计划上架 Google Play（个人侧载使用）。
- D10 普通照片（非实况）压缩也必须**正确处理并保留 GainMap / Ultra HDR（ProXDR）**，不得只压主图而丢弃增益图。
- D11 **HDR / 10-bit 视频「保真或跳过」，绝不降级**：识别到杜比视界、HLG/PQ、O-Log 等 10-bit HDR 视频时，只有在设备具备 **HEVC Main10（HDR10）编码器**、且压缩后产物经校验仍保留 HDR 信号（10bit 主档 + PQ/HLG 传递特性 + BT.2020 色彩标准 + HDR10 静态元数据）时才压缩；任一条件不满足即**跳过且不改动原文件**，并显示原因。**禁止把 HDR 静默转成 SDR 落地**（曾有的降级实现已按此条删除）。
- D12 **只处理相机原生静态图格式（JPEG / HEIF）**。PNG、BMP、WebP、AVIF 一律不处理：PNG/BMP 是无损格式（有损压缩必须改变容器格式、扩展名与 MIME），WebP/AVIF 属下载与第三方来源、且 AVIF 在 Android 平台无公开编码器。识别到即跳过，保持文件原样。

- D13（2026-10-07 安全修订）：停止 HEIC→JPEG 删除源文件式转换。无法保持原格式、路径和完整信息时跳过。任一 Failed 及时停止后续项；失败/中断恢复记录持久化，保护原始及安全备份。旧版无索引备份提供复制找回入口，不自动清理。

## Requirements

### 功能

压缩能力：

- F1 普通照片有损压缩：JPEG、HEIF/HEIC。PNG、BMP、WebP、AVIF 不压缩，识别后跳过（见 D12）。
- F2 实况照片整体压缩：主图 + GainMap + 内嵌 MP4（内嵌视频一并重编码）；压缩后仍被 ColorOS 相册识别为实况照片且可正常播放。
- F3 视频有损压缩：覆盖 HEVC / H.264 / AV1 / VP9。
- F4 压缩后原地替换（同一存储路径 / 媒体库条目，位置不变）。
- F5 完整保留元信息：EXIF / XMP / IPTC（地点、相机、拍摄参数、时间等）；实况照片还需保留 oplus 私有字段；普通照片需保留 GainMap；人像模式需保留景深信息。
- F6 保留文件创建时间与修改时间（含系统媒体库中的时间字段）。
- F7 唯一编号去重：已处理媒体不再重复压缩；编号同时存在于本地数据库与文件内元数据标记（见 D5），支持识别"是否已压缩处理过"。

界面与流程：

- F8 首页总览看板：未压缩媒体张数与总大小、已压缩媒体张数与总大小、已节约空间及百分比。
- F9 未压缩页：**二级结构 —— 一级列出图集，点入后看该图集的图片**；**图集与图片均可勾选**并批量压缩；图片支持**长按查看信息预览**；图集内可按类型筛选。
- F10 已压缩页：**同样为二级结构（图集 → 图片）**；图集与图片均可勾选并批量还原（限制在回收站保留期 30 天内）；图片长按查看信息预览；图集内可按还原状态筛选。
- F11 回收站：展示已压缩媒体的原始文件备份，支持手动清理（全部 / 选中），并到期自动清理。
- F12 设置页：普通照片、实况照片、视频三类**分别独立**设置压缩质量档位。
- F13 界面基于 Compose + Material 3（Material You），跟随系统动态取色与深浅色自适应，现代简洁、逻辑清晰。

安全与可恢复：

- F14 校验失败自动回滚，原文件保持可用；处理中断不破坏原文件。

### 约束

- C1 质量目标：肉眼不可见的细节损失。
- C2 同一份媒体只压缩一次，不产生二次压缩。
- C3 目标与验收环境：真我 GT7 Pro / ColorOS 16 / Android 16。
- C4 不满足元信息保留或兼容性条件的媒体**宁可不压缩也不破坏**，并给出明确原因，不得静默放宽。
- C5 硬门槛（识别到即跳过、不修改原文件）：RAW / DNG；人像模式的景深 / 深度信息无法完整保留时；慢动作与延时的播放速率语义无法保留时；未知或无法安全重写的容器；**10-bit HDR 视频中无法保真的情形**（设备无 HEVC Main10 编码器，或保真校验未通过，见 D11）。
- C6 普通照片的 GainMap / Ultra HDR 必须完整保留（见 D10）。

## Acceptance Criteria

- [ ] AC1 对样张类实况照片压缩后，ColorOS 相册仍将其**识别为实况照片**并可播放内嵌视频，HDR/GainMap 表现不被破坏。
- [ ] AC2 压缩后文件体积显著下降，且抽样对比无肉眼可见画质差异（判定方法需可复现，见 design.md 的质量标定项）。
- [ ] AC3 压缩后 EXIF/XMP/IPTC（含定位、相机信息、拍摄时间）与系统媒体库时间字段保持一致（对比压缩前后的读取结果）。
- [ ] AC4 压缩后文件创建时间与修改时间与压缩前一致；存储路径与相册条目位置不变。
- [ ] AC5 同一媒体第二次进入处理范围时被识别并跳过，不产生二次压缩。
- [ ] AC6 处理过程中断（断电 / 被杀进程）时，原文件不被破坏，可安全重试。
- [ ] AC7 三类媒体（普通照片、实况照片、视频）在真机上均可完成压缩并进入"已处理"状态。
- [ ] AC8 回收站行为：压缩成功后原文件可从应用内还原且与压缩前一致；保留期到期后被清理；校验失败时原文件未被修改。
- [ ] AC9 首页看板数据与实际一致：未压缩 / 已压缩的张数与总大小、节约百分比可核验。
- [ ] AC10 未压缩页多选批量压缩、已压缩页多选批量还原均可正常完成；超出 30 天的条目不可还原并给出明确提示。
- [ ] AC11 设置页三类压缩质量档位相互独立，修改后对相应类型生效。
- [ ] AC12 不满足条件的媒体（如 HEIC 元信息无法保留、设备无对应编码器、RAW/DNG、人像景深无法保留、设备无 HEVC Main10 编码器的 10-bit HDR 视频）被明确标记为跳过并显示原因，未修改原文件。
- [ ] AC13 带 GainMap 的普通照片压缩后，相册中 HDR / ProXDR 显示效果与压缩前一致（对比真机观感）。
- [ ] AC14 非相机原生格式被识别并跳过且显示原因、文件未被修改：PNG、BMP、WebP、AVIF、动图（GIF / 动态 WebP / 动态 AVIF）、MOV·MKV·WebM·3GP·TS 视频。
- [ ] AC15 两页均为二级结构（一级图集列表、二级图片网格）；图集与图片都能勾选并触发对应的批量压缩 / 还原；图集级与图片级的数字必须自洽（可还原项数不得大于总项数，勾选统计、按钮文案与确认文案数字一致）。
- [ ] AC16 图片长按弹出信息预览（文件名、类型、图集、大小、拍摄时间、地点、状态 / 跳过原因）；键盘有等价路径：Enter 打开信息、Space 勾选。

## 不在首版范围

- 云端上传 / 同步、跨设备去重。
- 自动扫描全库并后台批量压缩（D2）。
- GIF / 动态 WebP / 动态 AVIF 等动图。
- MOV / MKV / WebM / 3GP / TS 等 MP4 以外的视频容器。
- PNG、BMP、WebP、AVIF 图片（不处理，见 D12）。
- RAW / DNG 的压缩（仅识别并跳过，见 C5）。
- 10-bit HDR 视频**降级为 SDR 的压缩**（按 D11，要么保真、要么跳过；HDR 源永不静默转 SDR 落地）。
- iOS 导入的实况照片（非 oplus 来源）。
- 非 ColorOS 设备适配。
