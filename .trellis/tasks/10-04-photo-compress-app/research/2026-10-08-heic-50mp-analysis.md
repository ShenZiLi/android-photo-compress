# 5033 万像素 HEIC 被像素上限拒绝：只读分析

用户提供 `IMG20241010191358.heic`，要求先分析“HEIC 未压缩，原片已保留：HEIC 文件或像素过大，已保留原片”的原因；本轮不修改产品代码或压缩样例。

## 样例实测

| 项目 | 实际值 | 当前规则 |
| --- | --- | --- |
| 文件大小 | 5,145,851 字节，约 4.91 MiB | 不超过 64 MiB，满足 |
| 主图尺寸 | 8192 × 6144 | 50,331,648 像素，超过 20,000,000 上限 |
| 主图形式 | 静态 grid，16 × 12，共 192 个 512 × 512 tile | tile 数允许 1–256；此项未超过 |
| 位深及编码 | HEVC profile 1，8 位 YCbCr 4:2:0 | 与 8 位范围一致，不代表后续全部校验已通过 |
| 其他基本信息 | prof 色彩配置，无 alpha、depth 或旋转裁切 | 尚未运行编码/重组/输出校验 |

尺寸同时通过 macOS `sips` 与 libheif `heif-info` 读回，并解析 `ispe/hvcC` 交叉核对。读前、读后的原文件 SHA256 相同：`a2cc1e4f96509f7d9d6a01edd1c340e961a675beba09a2252933f5a08bedd3a9`。样例没有拷入跟踪目录，没有读出或保存私人 EXIF 内容。

## 直接原因与调用路径

`HeicContainer.kt:53` 将文件大小和像素数放在同一 `require`：

```kotlin
require(bytes.size <= MAX_FILE_BYTES && width > 0 && height > 0 &&
    width.toLong() * height <= 20_000_000) {
    "HEIC 文件或像素过大，已保留原片"
}
```

本样例的失败条件是最后一项，像素数约为允许值的 2.52 倍。64 MiB 文件限制没有触发。`HeicCompressor.compress` 在读取源字节后构造容器，之后才调用 `BitmapFactory.decodeFile` 和 `HeifWriter`，因此错误发生在解码、编码和原片写入前。

用本工程现有编译产物离线直接构造 `HeicContainer`，实际返回 `IllegalArgumentException: HEIC 文件或像素过大，已保留原片`，与用户提示一致。`CompressionEngine.compressHeic` 捕获该异常并返回 Skipped，只有后续编码/完整性/收益检查完成才调用原地写入的 `commit`。本轮未操作设备媒体、运行压缩或新增测试套件。

## 为什么文件小仍会拦截

压缩文件体积与解码内存不同。按当前 ARGB_8888 解码路径估算，50,331,648 像素的一张 bitmap 为 192 MiB。输出校验时原 bitmap 尚未 recycle，又解码一张输出图，仅两张像素缓冲就约 384 MiB，另外还有 HEVC 编码器、源字节及容器重组等开销。

20,000,000 是 App 固定的处理范围，代码没有依据设备实时内存或编码器能力计算此阈值。本次拒绝不能说明设备已发生内存不足、编码器不支持或文件损坏；这些后续情况没有执行到。

## 后续修复方向（未实施）

如需支持此类原尺寸照片，应先评估大图处理内存峰值与编码器/grid 能力，再决定扩大范围、调整缓冲生命周期或采用分块路径，并保留现有元数据/HDR/完整性与回滚检查。提示可拆分文件超限与像素超限，显示实际尺寸及上限。不能以通过尺寸门槛承诺整个压缩流程已兼容。
