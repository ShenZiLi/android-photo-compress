## 二、端到端实测（模拟器）

测试素材：真实 oplus 实况照片 1 张（12,478,846 B）、合成相机类 JPEG 4 张、H.264/HEVC/AV1/VP9/10-bit HDR/MOV 视频各 1 条、PNG/WebP/BMP/GIF 各 1 张。

### 还原与回收站

- 4 张 JPEG 压缩后还原，与本地原始文件 **SHA-256 完全一致**（4/4 `match=True`）。
- 回收站「清理全部备份」后已压缩照片仍在「已压缩」页，仅标记为不可还原。
- 保留期到期清理由 `RecycleCleanupWorker`（WorkManager，每日 + 启动即时）执行。

### 去重（F7 / AC5）

模拟「重装 / 清除应用数据」（`adb shell pm clear`）后**账本为空**，应用仍通过文件内标记识别出已压缩项：

| 标记位置 | 覆盖媒体 | 清数据后识别 |
|---|---|---|
| JPEG APP1 XMP（`photocompress:PCId`） | 普通照片、实况照片 | ✅ 5/5 识别为「已压缩」，不再出现在「未压缩」 |
| MP4 顶层 `uuid` box | 独立视频 | ✅ 2/2 识别 |

> 副产物验证：对已压缩且无标记的旧文件再次压缩时，`vid_av1` 因"压缩后体积未减小"被**自动跳过**，说明"体积不减小即不改动原文件"的保护生效。

## 三、验收标准逐条结论

| AC | 结论 | 依据 / 限制 |
|---|---|---|
| AC1 实况压缩后相册识别为实况、可播放、HDR 正常 | ⚠️ **部分验证** | 容器结构、EXIF、增益图、内嵌 MP4 均已逐项验证；**ColorOS 相册实际识别与 HDR 观感无法在 AOSP 模拟器验证，须真机复验** |
| AC2 体积显著下降且无肉眼可见差异 | ⚠️ **部分验证** | 体积下降已实测（照片 16–52%、实况 81%、视频 29–65%）；"肉眼不可见"未做人工观感判定，且自动指标在模拟器上无参考价值 |
| AC3 EXIF/XMP/IPTC 与媒体库时间字段一致 | ✅ 已验证 | EXIF 段逐字节一致；XMP 其它命名空间保留（单测）；`DATE_TAKEN` 由 EXIF 派生 |
| AC4 创建/修改时间一致、路径不变 | ⚠️ **部分验证** | 路径不变、mtime 一致、mtime 还原均已验证；**FUSE 下 birth time 无法保留**，`DATE_ADDED` 平台禁止应用改写（详见能力报告"修正 1"） |
| AC5 二次进入被识别并跳过 | ✅ 已验证 | 账本 + 文件内标记（JPEG XMP / MP4 uuid box）双重识别，已用清数据场景验证 |
| AC6 中断不破坏原文件 | ✅ 已验证（单测） | 先备份后写入；写入异常自动从备份回滚并恢复 mtime（`InPlaceRewriterTest`） |
| AC7 三类媒体均可完成压缩 | ✅ 已验证 | 普通照片 / 实况照片 / 视频均实测成功（见体积表） |
| AC8 回收站行为 | ✅ 已验证 | 还原后 SHA-256 与原始一致；清理备份不影响已压缩文件；到期清理由 Worker 负责 |
| AC9 看板数据与实际一致 | ✅ 已验证 | 统计直接读 `File.length()`，规避媒体库缓存滞后；界面对照截图核对 |
| AC10 多选批量压缩/还原 | ✅ 已验证 | 图集级与图片级批量均已实测；超期/已清理项不可选并给出说明 |
| AC11 三类档位独立生效 | ✅ 已验证 | 设置页三类独立持久化（Room）；压缩时按类型取对应档位 |
| AC12 不满足条件者被标记跳过且未改动原文件 | ✅ 已验证 | 10-bit HDR / MOV / PNG / WebP / BMP / GIF / HEIC 均按 C4 跳过并显示原因 |
| AC13 GainMap 照片压缩后 HDR 效果一致 | ⚠️ **部分验证** | 增益图**逐字节保留**（结构上不可能劣化）；相册 HDR 观感须真机复验 |
| AC14 非相机原生格式跳过且未改动 | ✅ 已验证 | 判类单测 + 模拟器实测（文件大小未变化） |
| AC15 二级结构、勾选自洽、按钮与确认文案数字一致 | ✅ 已验证 | 图集项数 = 图集内全部媒体数；可压缩/可还原数 ≤ 项数；按钮、确认框、统计同源 |
| AC16 长按信息面板 + 键盘等价路径 | ✅ 已验证 | 长按信息面板已实测（含大小/拍摄时间/跳过原因）；键盘路径用 D-pad 方向键聚焦 + `Enter` 打开信息面板已实测通过（`Space` 走勾选分支） |

## 四、已知限制（须真机复验或后续版本处理）

1. **ColorOS 相册识别**：实况照片重组后的相册识别 / 播放 / HDR 观感只能在真我 GT7 Pro 上确认。
2. **时间字段**：`birth time` 与 `DATE_ADDED` 受 Android 平台限制无法保留（见能力报告修正 1）。
3. **视频编码器**：模拟器只有软件编码器（HEVC 上限 512），因此实况内嵌视频在模拟器上回退为 1650×1238 H.264；真机有硬件编码器时预期保持原分辨率原编码。
4. **VP9 输出**：MediaMuxer 无法把 VP9 封装进 MP4，输出编码固定为 HEVC / H.264 / AV1（VP9 可正常作为输入）。
5. **HEIC**：平台无公开途径向 HEIF 写回 EXIF/XMP，按 C4 跳过（不降级妥协）。
6. **大库性能**：扫描时对每个 JPEG 读取 256 KB 头部用于实况/标记识别，超大媒体库（万级）首次扫描耗时较长；未实现 `media_scan_cache` 持久缓存。
7. **压缩质量**：单元测试与体积数据可复现，但"肉眼不可见"这一主观标准需人工在真机样张上判定。
