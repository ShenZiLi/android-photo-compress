# 无收益图片归类变更边界

用户要求：删除“压缩后体积未减小”后的尺寸括号，将这类图片从未压缩页移入已压缩页，标记“已跳过”。

当前问题：普通 JPEG、实况、视频提示包含不同尺寸；Skipped 仅发消息，不进入账本，因此扫描后仍在未压缩页。

实施范围：

- `core/compress/CompressionEngine.kt`：统一无收益结果，区分无收益与其他跳过；为图片持久登记不改写源文件的 SKIPPED 记录。
- `data/ledger/Ledger.kt`：沿用现有表字段增加状态常量，零收益、无备份；不变更数据库结构。
- `ui/AppUiModel.kt`：未压缩和已压缩共用有效记录规则，确保跳过原片不计节省且不可还原，文件改变后可重新进入处理范围。
- `ui/screens/AlbumsScreen.kt`、`ui/RootScreen.kt`：跳过标记、独立筛选、正确图集摘要和信息面板，避免显示过期或备份已清理。
- 版本、README、规范与会话记录同步交付。

不把格式不支持、失败、取消归入 SKIPPED；本次视频只统一提示，不改变其分页规则。源文件不写入 XMP，不创建恢复备份，跳过状态依赖本地账本，清除应用数据后需重新判断。

验收计划：构建调试及正式 APK；在现有 API 36 虚拟机通过原生 UI 处理专门生成的低质量 JPEG，核对原片摘要/时间不变、两页归类、不可还原与重启后状态；同时核对有效压缩图片继续提供备份和还原。遵循开发者指令，不新增或运行测试套件。

## 验收结果（0.1.24）

- 调试/正式构建成功，Room 表结构仍为 v5；新 APK 覆盖安装 API 36 虚拟机成功。
- 原生 APP 压缩同一合成图集：低质量 JPEG（156,334 字节）无收益，持久记录 SKIPPED，大小前后相等、无备份、无恢复截止日期；高质量 JPEG 从 1,554,706 字节压至 521,367 字节，记录 DONE 并保存备份；PNG 未产生处理记录。
- 无收益提示只包含“压缩后体积未减小”；混合图集显示“可还原 1 项 · 已跳过 1 项”。网格正常展示原片并标记“已跳过”，筛选只显示该项，信息面板显示“原片未改动，无需还原”。
- 无收益 JPEG 及不支持 PNG 的原始摘要、inode、纳秒修改时间与 MediaStore ID/日期保持不变。
- 关闭进程后重新启动，混合图集和跳过状态保持；原生还原确认只包含一张成功图片，还原后该图集在已压缩页显示“1 项 · 153 KB”“已跳过 1 项”。三份合成原片最后摘要、inode/mtime 均与处理前一致。
- 最终无未提交个人媒体；原生截图、数据库快照、合成副本、原始诊断输出均在忽略目录。
- 静态检查限制：`:app:lintDebug` 报 2 个已有 WrongConstant 错误，位于 `core/video/VideoTranscoder.kt` 358/377 行，`MediaExtractor.sampleFlags` 直接传给 `MediaCodec.BufferInfo.set`。通过 HEAD 原文及该文件零差异确认与本次变更无关。Trellis 检查要求超出变更边界的修复先记录证据，本次不扩大到视频转码修改。正式/调试构建与发布必需 Lint 成功，但不得称全量 Lint 已通过。
