# HEIC 报错后照片丢失：安全修复与全局故障排查（2026-10-07）

## 用户需求与处理范围

用户反馈 HEIC 转换报“无法恢复媒体日期、回退未通过、备份已保留”后照片消失，要求修复并检查其他报错丢图风险。用户明确提供一张 HEIC 供安卓虚拟机验证。本次为 0.1.21 安全修复；MPF 扩展仍待后续继续，不与安全修复合并发布。

## 代码根因与边界

- 旧 HEIC 转换先物理删除源，再扫描 JPEG 和删除旧 URI；媒体日期失败回退时，又会删除转换产物并删除旧 URI。MediaProvider 删除媒体行可同时删除文件；不同卷 URI 字符串也可能是同一条目的别名。文件、索引和日期没有共同安全提交边界。
- `restoreDates` 把 update 影响行数 1 当作必要条件；系统可能拒绝只读日期写入或返回 0，即使值本身未改变。修订后先读回，只有值不符合要求才尝试更新，最终仍以读回一致为判据；没有放宽日期要求。
- JPEG/实况/视频失败备份及旧 HEIC 失败备份可能不在账本内，上一版无账本残留清理可能删除唯一原片；缺少持久恢复入口。
- 旧还原先写原片再删除转换图、调用 reindex、删除备份，且账本删除在引擎返回之后；同步或账本失败无法安全提交。清除 JPEG 标记还会改变原始恢复字节与 MPF 布局。
- 未连接用户手机，不能把以上代码风险当成已读取真机文件的逐张诊断；本次实际验证使用独立虚拟机和副本。

## 修复

1. HEIC 在判类及引擎两层安全跳过，停止 HEIC→JPEG 删除源式转换；缓存逻辑版本 +1，升级后全量更新旧可压缩标记。
2. 移除生产流程的 reindex/delete URI 操作。只扫描存在文件并验证路径、尺寸、发布状态和时间；旧转换 JPEG 还原时保留转换副本。
3. 原地压缩写前将备份、SHA-256、原路径、纳秒 mtime、媒体信息和事务编号保存为 AtomicFile 恢复记录。回退/提交完整完成后才结束；失败项保护备份并在回收站显示“恢复原片”。同进程全局锁串行保护原子文件访问。
4. 还原前先校验原始备份摘要，保存当前照片安全副本；原片、媒体库、账本回调均通过才删除正常备份。不再清除备份元数据或媒体 URI。
5. 手动及到期清理均保护恢复记录引用的原始/安全备份；媒体已缺失或大小不符合账本时保留可能唯一剩下的备份。旧无索引文件不再自动删除。
6. 回收站“找回照片”把未登记备份复制到独立“轻存恢复”图集，CREATE_NEW 避免覆盖，并校验字节；保留私有原始备份。旧备份不包含原路径与系统日期，导出不能冒充完整恢复这些信息。
7. 压缩或还原遇到 Failed 停止后续项、及时提示；历史已完成结果保持。复制和恢复增加同文件及私有备份目录边界守卫。

## 故障注入验收

独立 Android 16/API 36 虚拟机，未操作用户手机；测试只创建独占图片/URI和明确提供 HEIC 的私有缓存副本。`MediaSafetyTest` 9 项通过：

| 场景 | 实际断言 |
| --- | --- |
| 用户 HEIC 副本 | 安全跳过，SHA-256、inode、mtime 不变 |
| 媒体日期校验失败 | 写后回退原始字节和时间；恢复记录重建读取，清理不能删除保护备份 |
| 账本发布回调失败 | 原片 SHA 和 inode 不变，媒体 URI 保持 |
| 发布后取消 | 当前项回退原始字节，恢复入口正确结束 |
| 备份损坏 | 覆盖前拒绝，现有照片摘要不变 |
| 磁盘媒体缺失 | 清理保留唯一备份，不注销索引 |
| 还原账本回调失败 | 原片已恢复，备份与恢复入口保留；重试回调收到正确账本编号 |
| 写中断模拟 | 耐久记录可在新实例读取，重复压缩被拒绝；恢复原始摘要和修改时间 |
| 旧 HEIC 转换还原失败 | 使用用户 HEIC 副本，错误后 HEIC 原片、JPEG 转换图、原始备份均存在且摘要符合 |

未运行旧的跨用户媒体目录测试，也未使用真实个人图库自动选样。测试日志和样本均在忽略目录。

## 原生界面验收

- 创建一张只有 10 字节残留的模拟 JPEG 和对应完整恢复记录，原生点击回收站“恢复原片”及确认：原文件逐字节恢复，记录完成，相册可索引，私有备份保留。
- 将用户 HEIC 副本作为旧版无账本备份，原生点击“找回照片”及确认：恢复图集中 HEIC SHA-256 与桌面样本相同，原始备份仍在；没有覆盖已有照片。
- 不存在待恢复记录后的页面不会把有异常备份的回收站标为“空的”；崩溃缓冲无新增异常。
- Debug、签名 Release、专项测试 APK 构建通过，Release lintVital 通过；正式签名符合项目既有证书，0.1.21 / versionCode 22。

## 已检查的生产删除路径

JPEG/实况/MP4 统一 commit 采用上述持久恢复；编码错误发生在原文件改写前；转码及 MP4 元数据替换仅删除 Attempt 管理的私有临时文件。HEIC 源删除路径已经移除。正常还原备份清理发生在文件/媒体/账本完成后。恢复原片不删除原始备份，未知备份只能复制导出。诊断模块的删除路径针对自行生成探针文件/URI，不参与用户媒体压缩。

## 限制与后续

- HEIC 原格式压缩尚未实现，本版明确跳过；不能把安全禁用转换说成已实现 HEIC 原格式压缩。
- 用户手机上已经丢失的照片没有直接读取或恢复；原始备份尚在时可用新版“找回照片”，否则需另行检查实际设备。
- 进程中断验证为持久恢复记录和半成品故障模拟；没有宣称真实断电、磁盘物理损坏、所有机型故障都已验证。
- 历史账本仅记录秒精度时间；优先使用仍符合原日期的现存文件纳秒 mtime。旧备份缺失的系统日期/路径无法凭空还原，不放宽媒体完整性标准。
- 仅本地交付 APK 与 Git 提交，未推送或 GitHub 发布。MPF 多图扩展待继续。
