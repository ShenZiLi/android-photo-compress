# PNG 开关与 JPEG 转换（0.1.28）

用户确认：设置页增加“压缩PNG”开关；普通照片格式说明为“JPEG / HEIF / PNG”，质量共用普通照片档位；PNG 处理结果转 JPEG。透明区域不能用 JPEG 保留，因此跳过，不自动铺底色。

## 变更边界

- 设置与 Room：compressPng 默认关闭；v5→v6 非破坏迁移，仅新增布尔列。
- UI、候选与缓存：设置开关即时作用于未压缩候选，并在引擎入口再次检查。判类版本升级为 3；已转换 JPEG 仍使用既有 XMP 去重。
- PNG 编码：8 位非交错静态 PNG；检查 CRC、完整解压和像素透明度，使用 JPEG 92/85/76。保持尺寸与平台解码色彩空间，EXIF TIFF 直接迁移、XMP 合并标记，所有非 IDAT 原始块按顺序存为 JPEG APP15 归档。无法在 JPEG 常规字段承载的 PNG 扩展不会静默删除；专有归档不冒充通用相册可读取的标准字段。
- 原地转换：目录不变，后缀 .png→.jpg 是用户本次明确允许的格式转换例外。同名目标存在时跳过，不覆盖。用 MediaProvider 改名复用同一 URI/ID/inode，禁止先删除 PNG 再另建 JPEG。
- 事务：改写前持久保存 PNG 备份、原日期、精确 mtime、原 inode 和转换路径。失败/取消独立撤销登记，再原地写回 PNG、改回原名、校验相册与日期；完整通过后清理本次临时备份。中断后按媒体 ID/inode 定位当前文件，失败条目留未压缩页。
- 还原：成功 JPEG 的备份是原 PNG；还原同一文件内容与原 .png 文件名，不产生遗留 JPEG，不删除或重建媒体库条目。失败恢复入口保护原始和安全副本。
- 不修改 JPEG/MPF/HEIC/视频原有压缩策略；不推送、发布或操作真实个人照片。

## 原生验收结果

API 36 原生 APP 使用新生成的独占合成媒体：开关重启持久、旧账本保留、三档 JPEG 转换/改名/元数据/时间身份、透明/APNG/目标冲突保留、还原 PNG 字节与路径、数据库失败回滚、中断恢复与取消仅当前项。原始媒体、数据库和截图仅保存在忽略目录。按开发者要求不新增或运行测试套件，只更新既有 PNG 判类断言。

- v5→v6 后旧 5020 条账本保留。全部验收还原后仍为 5020 条，无数据清库。PNG 开关与普通照片档位经原生 UI 修改，关闭/重启后仍关闭；普通照片说明显示 JPEG / HEIF / PNG。
- 同一合成 768×512 不透明 PNG，原始 1,078,059 B：高质量 JPEG 116,968 B（减少 89.2%），平衡 74,393 B（93.1%），更省空间 52,085 B（95.2%）。仅为该合成样本收益，不推断真实照片的固定压缩率。
- 三档实际 JPEG 格式与 q=92/85/76 账本一致；同一媒体 ID、inode、纳秒 mtime、DATE_ADDED/DATE_MODIFIED/DATE_TAKEN 保持。JPEG APP1 EXIF 与原 PNG TIFF 完全一致，APP15 归档与所有原非 IDAT 块逐字节一致，标准 XMP 唯一标记可被媒体扫描识别。
- 无 EXIF/XMP 的合成 PNG（原始 DATE_TAKEN=null）正常转 JPEG，null 和其他日期/身份保持。四张成功结果通过原生批量还原，全部恢复 PNG 字节/原名，无遗留 JPEG；备份与本次恢复入口清理。
- 透明 PNG 原生提示“PNG 含透明区域，无法保留透明度，已保留原片”。APNG 在扫描阶段标为不支持，原文件保留。同名 JPEG 冲突提示“同名 JPEG 已存在，已保留 PNG 原片”；两个文件摘要均不变。
- 使用仅针对自建 PNGJPEG-Fail 的 SQLite INSERT 触发器注入真实登记异常。JPEG 已写入/改名后事务回滚，PNG 字节、文件名、inode、精确 mtime、媒体 ID/日期均恢复；无残留本次账本、PNG/JPEG 备份或恢复记录。最后重建 APK（含安全副本、MIME 校验与扫描水位定向更新）重复此项通过。
- PNGJPEG-Cancel 在登记延迟中通过原生任务栏取消：只还原当前 PNG，之前三张成功 JPEG 仍为 DONE、保留备份。延迟触发器与失败触发器在结束时全部删除，临时图集过滤恢复。
- 模拟已持久化转换恢复记录，通过实际启动恢复代码写回 PNG/原名。故意错置 null 日期的记录只能完成字节恢复，继续保护并在未压缩页提示失败；保留真实 null 标记的记录完成日期/账本/备份收尾。未将失败的时机采样误报为真实强杀中途验收通过。
- 调试/正式构建、正式签名和 0.1.28/code29/轻存包信息检查通过，最新调试 APK 模拟器覆盖安装及冷启动成功。完整 Lint 仍有未修改的 VideoTranscoder 两项 WrongConstant 既有错误；本次新增的 KTX 建议已修正，未以构建冒充全量 Lint 通过。
- 本轮未安装真机、未操作真实个人照片；真机厂商改名兼容性、特殊 ICC/HDR、超过当前安全范围的 PNG 与文件创建时间均不以模拟器结果替代。

PNG 结构、过滤和未知块策略参考 [W3C PNG 规范](https://www.w3.org/TR/png-3/)；同一媒体条目改名参考 [Android 共享媒体文档](https://developer.android.com/training/data-storage/shared/media)。
