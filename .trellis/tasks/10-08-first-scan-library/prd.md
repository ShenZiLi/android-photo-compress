# 修复首次扫描结果和图集过滤为空

## Goal

首次扫描取得媒体后，首页、未压缩/已压缩列表和设置页图集过滤立即展示扫描结果；后续媒体和设置变化正确更新派生结果。

## Requirements

- 首次扫描从空库到非空库时发布新的媒体库派生快照。
- 图集过滤名单展示全部扫描到的图集，排除图集后仍可重新开启。
- 图集排除、PNG 开关变化更新列表与统计。
- 后台计算期间若媒体、账本、恢复日志或设置改变，过期结果不得覆盖当前快照。
- 页面、图集层级、选中项或扫描进度改变不应导致有效快照丢失或重置这些状态。
- 保留已有扫描缓存、文件安全事务和后台计算机制。

## Acceptance Criteria

- [x] 以合成媒体证明首次扫描后的数量、占用、图集和过滤名单正确。
- [x] 验证设置变化、过期结果拒绝与导航/选择状态保留。
- [x] 修复前回归用例失败，修复后通过；调试构建与 Android Lint 通过。
- [x] 本地提交代码、测试、规范及任务/会话记录。

## Change Boundary

根因位于 `AppViewModel.rebuildLibrary` 的发布条件：它判断旧 `library.matches(current)`，输入改变时永远拒绝新结果。

将发布判断放入 `LibrarySnapshot.applyTo(UiState)`，由 ViewModel 的原子更新调用，检查新快照是否匹配当前输入。改动限于上述两个 UI 文件、专项回归、版本号及文档；不改变扫描、数据库或媒体文件处理。测试只构造内存对象，不处理个人媒体。

## Verification

见 [根因与验收记录](research/verification.md)。首次空库转换由合成回归验证；真机保留现有数据和扫描缓存，覆盖安装后验证增量扫描、首页和设置图集过滤。
