- 原 PNG 像素拒绝、透明拒绝和 JPEG 重名拒绝均已改为新行为；保留文件 32 MiB、非像素扩展 4 MiB、APNG/HDR/低色深/交错/损坏数据拒绝与媒体恢复契约。
- 仅使用 RMX5010 / Android API 36 上 `/data/local/tmp/qingcun-png-cases-01a11ab3/` 内的合成独占文件。临时诊断通过新 Debug APK 的完整 PngCompressor 运行；私有目标选择函数通过反射直接验证，不创建相册条目、不操作 app 数据库、不压缩相册原图、不安装 APK。

## 实际结果

| 案例 | 断言与结果 |
| --- | --- |
| 2000 万像素 PNG | 5000×4000，预检放行；完整压缩保持尺寸，24,294,052 → 8,316,980 字节（约减少 65.8%）；原文件 SHA 不变 |
| 8 位 RGBA | 600×240；不透明红约 `#FE0000`，半透明红约 `#FF7F7E`，全透明像素 `#FFFFFF`；尺寸、原文件 SHA 保持 |
| 16 位 RGBA | 同样尺寸与白底断言通过；原文件 SHA 保持 |
| 调色板 + tRNS | 同样尺寸与透明/半透明白底断言通过；原文件 SHA 保持 |
| PNG 行滤波 | 透明样例每行轮换过滤器 0/1/2/3/4；完整像素校验与 JPEG 解码通过，覆盖复用两行缓冲的预测器状态 |
| 普通重名 | 已占用 `same.jpg` 与 `same_1.jpg` 时选择 `same_2.jpg`；已有两文件 SHA 不变；空闲原名仍用 `free.jpg` |
| 长文件名 | 255 字节 ASCII 原名冲突后输出名称 255 字节；含补充 Unicode 码点的原名冲突后输出 253 字节；实际文件创建成功，无拆分码点，原文件 SHA 不变 |
| 广色域透明混合 | Display-P3 半透明红经原色彩空间白底混合后原生颜色为 `(1.0, 0.49804688, 0.49804688, 1.0)`；P3 色彩空间保持，无 sRGB 中转裁切 |
| 取消 | 完整压缩入口检查取消并抛出取消信号，原样例 SHA 不变 |
| 内存不足 | 有效 20000×20000 静态 RGB 合成 PNG，仅约 1.2 MB 文件；384 MiB 堆内在解码前拒绝，明确提示“PNG 可用内存不足”，原 SHA 不变 |

透明小样例的 JPEG 含标记和元数据后可能大于原 PNG；仅验证编码/透明行为，不将它们声称为引擎 DONE。引擎原有无体积收益 SKIPPED 契约保留。

## 诊断中修正的兼容性与环境问题

1. 默认 Gradle 全局初始化脚本强行添加仓库，与工程仓库策略冲突；改用现有项目专用 Gradle 用户目录，并统一 ANDROID_HOME/ANDROID_SDK_ROOT 后构建通过。未改全局配置。
2. 初次诊断在 16 位 RGBA 处表现为进程被系统终止。逐步诊断确认 parse、内存预算、完整像素校验、位图解码和 JPEG 编码均可运行；平台忽略首选 ARGB_8888 返回可变 RGBA_F16 / scRGB-nl。新增的严格 ARGB_8888 配置检查拒绝了此原有受支持路径，未捕获诊断异常被 Android 终止。已恢复 ARGB_8888/RGBA_F16 两种可变位图支持，16 位按 8 字节/像素预算；最终每个案例独立进程全部通过。
3. 复核修正数字后缀超出 255 字节文件名，以及整数 getPixels/setPixels 经 sRGB 造成广色域透明混合失色；最终 UTF-8 与原色彩空间诊断通过。
