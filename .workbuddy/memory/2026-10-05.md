## 10bit HDR 视频压缩：D11 由「首版不处理」改为「保真或跳过」

主体拍板：策略 A（跳过）+ 保留既有未提交改动继续迭代 + 代码与文档一起提交。

### 决策要点

- **核心原则**：HDR 源要么保真压缩，要么跳过；**禁止静默降级为 SDR 落地**。
- 三候选方案：A 跳过（采纳）/ B 降级+提示 / C 用户可选。选 A 的理由是「保留视频原始信息」是硬要求，
  降级即使有提示也构成事实违约，不应把决策成本转给用户。
- 未选 C 是首版不引入交互成本。

### 实现

- 删除 `HdrMode.SDR_CLEAR` 及「保真失败→自动转 SDR」整条降级链。
- 能力门槛 `MediaClassifier.deviceCanPreserveHdr`（`by lazy` 进程级缓存）。
- **判类保持纯逻辑**：`decideVideo` 的 `canPreserveHdr` 做成惰性提供器 `() -> Boolean`，
  仅在源为 HDR 时求值 —— 因为 JVM 单测里 `MediaCodecList` 是桩实现，非 HDR 路径不得触碰它。
  这是本次踩到的坑：默认参数会在调用点直接求值，导致 `getCodecInfos not mocked`。
- 新增 `VideoProbeRunner.scanHevcConfig`（直读 `hvcC` 取 profile/位深），
  `probe()` 在 MediaExtractor 缺省这两项时自动兜底。
- `buildColorPatch` 在「源无任何色彩标注」时按 BT.2020 + PQ 补齐 signaling。

### 样本实测（重要）

`local-test-media/videos/vid_10bit_hdr.mp4` 的真实属性：
- `hvcC` profile_idc = **2**（Main10）、bitDepthLumaMinus8 = **2**（10bit）

即「裸 10bit Main10、无 signaling」，正好是兜底链的靶子。

### ✅ U4b 结论：真机具备 HEVC Main10 硬件编码器

```
hevcMain10 encoder=c2.qti.hevc.encoder hw=true profiles=[1, 4, 2, 4096, 8192, 8] main10=true
hevcMain10Encodable=true
summary_line avc=true hevc=true vp9=false av1=true heif=true hevcMain10=true
```

→ **保真路径在这台机器上可用**，HDR 源不会被迫跳过。4K 可原分辨率编码（上限 8192）。

真机编码器要点：
- `c2.qti.hevc.encoder`（硬件，Main10/HDR10/HDR10Plus，8192）← 主力
- `c2.qti.hevc.encoder.hdr`（**HDR 专用**，XML 声明 `hdr-editing`，上限 4096）
- `c2.qti.dv.encoder`（杜比视界，8192）
- **VP9 无可用编码器**（`encoderAvailable vp9=false`）；AV1 仅软编（max 1920）
- 遗留观察点：`selectEncoder` 未显式偏好 hdr 专用编码器，U4c 时一并看

### 踩坑记录（重要，跨项目复用）

1. **ColorOS 16 加固 appops**：`adb shell appops set <pkg> MANAGE_EXTERNAL_STORAGE allow` 与
   `pm grant <pkg> android.permission.MANAGE_EXTERNAL_STORAGE` **均被拒**
   （`SecurityException: uid 2000 does not have MANAGE_APP_OPS_MODES` / `GRANT_RUNTIME_PERMISSIONS`）。
   → 「所有文件访问」只能**用户在系统设置里手动授予**。下次别在这上面浪费轮次。
2. **Git Bash 路径转换坑**：`adb shell "grep ... /vendor/etc/xxx.xml"`、`adb pull /vendor/etc/x .`
   会被 MSYS 改写成 `C:/.../PortableGit/.../vendor/etc/x`，表现为**静默无输出**或 `failed to stat remote object`。
   → 凡 adb 命令里含设备端绝对路径，**必须加 `MSYS_NO_PATHCONV=1`**。
3. adb daemon 本次会话反复 "not running; starting now"，偶发瞬时掉线；`kill-server` + `start-server` 可恢复。
4. 真机跑探针的完整链路：
   `assembleDebugAndroidTest` → `adb install -r <androidTest.apk>` →
   `am instrument -w -e class com.photocompress.app.DeviceCapabilityProbeTest com.photocompress.app.test/androidx.test.runner.AndroidJUnitRunner` →
   `adb logcat -d -s PCPROBE`
