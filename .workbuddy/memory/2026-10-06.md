### ⚠️ 网络踩坑（已沉淀到用户级记忆，此处只记要点）

沙箱代理的**域名白名单不含 `github.com`**（`api.github.com` ✓ / `codeload.github.com` ✓ / `github.com` ❌），
而直连 `github.com:443` 又被出站阻断 → 这就是「`gh` 能建仓库、`git push` 却失败」的原因。

**可用解**：本机 7890 端口有常驻代理（Clash），能通 `github.com`。

```bash
git -c http.proxy=http://127.0.0.1:7890 -c https.proxy=http://127.0.0.1:7890 push -u origin master
```

**关键**：只 export 环境变量**没用** —— 沙箱注入的代理会覆盖它，必须用 `-c` 显式指定。

**凭据现状**：`gh` 已登录（keyring，scopes 含 `repo`）；git 的 GCM 能自动取到凭据，**无需另配 token**。
（此条更正了用户级记忆里 09-22 版「本机无可用推送凭据」的旧结论。）

### ⚠️ 我犯的一个操作失误

执行 `env | grep -i proxy` 时，误匹配到 `CODEBUDDY_MCP_CONFIG`（含 "proxy" 字样），
**把整个 MCP 配置整段打进了终端输出**，其中含多个本地 MCP 服务的 Bearer token 与 LM Studio API key。
都是 `127.0.0.1` 本地服务的凭据、且只在本机终端回显，但已提醒主体勿外传该段日志。
**以后查看代理变量一律用精确匹配**：`env | grep -E '^(http|https|all)_proxy'`。
